# Data News Editorial Studio

把用户给出的主题推进为有观点、有证据、可审核、可交付的数据新闻。它是编辑部工作流，不是单纯的图表生成器。

## 读取顺序

- 任何正式视觉制作都读取 [visual_rules.md](visual_rules.md)。
- 形成审核稿、成品或交付清单时读取 [output_schema.md](output_schema.md)。
- 用户选择“长图型”“做成长图”“一张完整长图”或“超长数据新闻”时，必须先读取 `visual_rules.md` 的 **Long Infographic Production / 长图型高清生产规则**，并按 `output_schema.md` 的 **长图型交付规范**交付。

## 作品形态路由

先识别最终产品，再决定画布、叙事与交付方式：

1. **长图型**：一张连续纵向完整图片。内部允许拆分生产，最终不得交付成多张独立海报或分页截图。
2. **一张大海报型**：在单一固定画布中压缩表达核心结论与主要证据。
3. **链接型**：网页、H5、长滚动、翻页或交互产品；按设备、交互与加载性能设计。

若用户已指定形态，直接采用，不自行改成别的形态。只有在用户没有指定、且不同形态会显著改变结果时，才给出推荐。

## 不可违反的规则

### 1. 先观点，后图表

- 先形成可被数据验证的中心判断，再写完整叙事与图表计划。
- 图表是证据，不是文章本身。每张图只承担一个核心结论，并配有必要的解释或过渡文字。
- 不把“标题 + 若干图 + 一句总结”的数据汇总海报冒充完整数据新闻。

### 2. 一图一口径

- 同一数据系列优先使用同一来源体系、统计定义、样本范围、时间口径和单位。
- 发现口径不一致时，依次选择统一来源、拆图、正文解释；禁止静默拼接。
- 跨来源比较必须说明可比性和限制。不可比的数据不得为了画面完整被强行放进同一比较图。

### 3. 数据时效性

- 研究日附近的**当前现象、态度、意愿、行为和市场状态**，优先使用最近 1–2 年数据；最近 1 年优先，其次最近 2 年。
- 官方发布存在滞后时，使用最新可得数据并明确数据年份和发布时点。
- 较旧数据只可用于长期趋势、历史基线、制度或人口结构变化，以及确无更新数据的场景。
- 较旧的单次调查不得直接证明当下态度；必要时写成“较早研究曾发现”，并标记限制。
- 不能为了追新而破坏一图一口径。新旧数据定义不一致时，宁可拆图或放入正文说明。

为关键证据标记新鲜度：`CURRENT_0_1Y`、`CURRENT_1_2Y`、`OLDER_BUT_VALID_TREND`、`HISTORICAL_BASELINE`、`NO_NEWER_DATA_AVAILABLE` 或 `OUTDATED_FOR_CURRENT_CLAIM`。支撑当前结论的核心证据若为 `OUTDATED_FOR_CURRENT_CLAIM`，不得进入 `READY`。

### 4. 来源可追溯

每条关键数据记录指标、数值、单位、时间、地域、样本、统计口径、来源机构、发布时间和原始链接。媒体二次转述不能替代可获得的原始来源。

### 5. Image-2 的职责与边界

- 正式视觉资产、主题插画和经过锁定数据约束的图表视觉，使用 **Image-2（用户旧称 GPT-Image-2）**。若不可用，先说明，不能静默换模型。
- 代码可用于清洗、计算、验证、排版与无损组装，但不得把 Python、ECharts、SVG 或 BI 工具的默认图表直接当成正式视觉成品。
- 所有数值、年份、单位、排序和百分比均为锁定信息。Image-2 生成后逐项核对；错误资产必须定向修改或重生成。
- 标题、正文、关键数字、数据标签和来源优先使用最终画布中的真实可编辑文字，不依赖图像模型生成小字。

### 6. 长图不是 Word 文档

- **禁止使用 Word 排版长图，禁止把 Word 当作长图母版，也禁止采用“Word → PDF → 拼成长图”的生产路径。**
- 长图必须在可精确控制的连续纵向画布中完成。可使用支持可编辑文字和无损导出的专业设计画布或可控渲染工作流；保持文字可编辑直至最终导出。
- Word 仅在用户另外明确要求独立 DOCX 报告时使用，该报告与长图是两个不同交付物。
- **本版本暂不把 PDF 纳入长图生产或默认交付。** 后续只有在用户重新启用并通过实际稳定性验证后，才另行增加 PDF 路径。
- **不预设可画（Canva）为长图排版工具。** 在可画尚未通过超长画布、真实文字、2160px 导出和放大清晰度验证前，不得依赖它完成正式长图。

### 7. 锁定视觉系统

- 正式出图前建立一份全篇 `Visual Style Lock`，至少锁定画布、网格、背景、配色、字体层级、图表语法、插画语言、装饰、留白、来源样式和禁用项。
- 同一项目的分段生成、补图、修改和重生成必须继承同一份锁定，不得自行换风格。
- 参考图若只用于说明“长图形式”，只学习连续纵向阅读与模块组织；不得继承其配色、字体、插画、纹理、装饰或题材气质。

## 标准工作流

### Gate 1：选题与证据

1. 收窄问题，说明公共性、时代性、信息增量与可获得证据。
2. 搜集并核验数据，建立来源表和一图一口径映射。
3. 区分来源事实、衍生计算和编辑推断。

通过条件：核心判断有足够证据；关键数字可追溯；当前性结论满足时效规则。

### Gate 2：叙事与文案

1. 写出一句中心判断。
2. 完成导语、章节推进、图后解释、过渡和结尾。
3. 再确定图表数量与图型。用户要求常规专题长图时，可按约 8–10 张图、800–1000 字规划，但以内容需要和用户要求为准，不为凑数灌水。

通过条件：每一模块都推进中心判断；图表与文案各有职责；没有空泛结论。

### Gate 3：单图设计卡

每张图锁定：图号、结论式标题、口径副标题、完整数据、来源、图型、视觉母版、重点数字、编辑动作和 Image-2 资产需求。

通过条件：结论、口径、数据、视觉和提示输入均明确，才允许进入生成。

### Gate 4：正式视觉生产

- 建立并批准全篇 `Visual Style Lock`。
- 每张图或每个视觉资产单独生成、单独核验；用户只改一张时，只返工相关资产和受影响模块。
- 长图型必须执行 `visual_rules.md` 的长图流程，不得一次性让 Image-2 生成整张含大量图表与长文的最终稿。

### Gate 5：组装、质检与交付

- 按作品形态完成最终画布，不把内部过程件当成成品。
- 核对数字、年份、单位、中文、来源、比例、阅读顺序、视觉一致性和导出尺寸。
- 长图必须完成全图概览、100% 原尺寸与 200% 放大检查；任何关键文字、标签、来源或接缝不清晰即返工。
- 最终按 `output_schema.md` 输出成品、审核结果和仍需用户决定的事项。

## 失败条件

出现任一项即不得标记 `READY`：

- 核心数字无来源，或图表结论与数据不一致。
- 当前性结论主要依赖过时且不可外推的数据。
- 同图口径被静默混合。
- 标题不是结论式，文案没有中心判断或图后解释。
- 图像中的数字、年份、单位、排序、比例或中文错误。
- 视觉呈现退化为 Dashboard、BI 后台、SaaS 卡片或默认代码图。
- 参考图污染已锁定风格。
- 长图使用 Word 排版，依赖 PDF 中转，或未经验证便依赖可画完成正式成品。
- 一次性让 Image-2 生成含 8–10 张图和 800–1000 字的整张超长最终稿。
- 长图最终被交付为多张分段图、存在明显接缝，或在 100%/200% 检查中不可读。
